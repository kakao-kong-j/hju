# 항저우 여행 지도 웹사이트 설계

작성일: 2026-10-16

## 목적과 승인된 범위

사용자는 프로젝트의 이미지로 웹사이트를 만들고, 지도에서 각 장소를 보며 마우스 호버 또는 클릭으로 상세 내용을 확인하고, 여행 계획을 볼 수 있기를 요청했다. 지도 중심 화면에 장소 목록과 일정 편집을 연결하는 구성을 승인했다.

현재 프로젝트에는 `IMG_6749.JPG`부터 `IMG_6755.JPG`까지 이미지 7장만 있다. 기존 코드와 Git 저장소는 없다. 이미지는 항저우의 저장 장소 목록을 촬영한 스크린샷이다. 스크린샷에 표시된 27개 장소를 서로 다른 항목으로 제공한다.

한국어 화면을 기본으로 하되 중국 현지에서 장소를 찾을 수 있도록 중국어 원문을 함께 표시한다. 여행 날짜와 기간은 전달받지 않았으므로 확정 일정으로 표현하지 않는다.

## 선택한 접근

지도 중심, 일정 중심, 사진 갤러리 중심 화면 중 지도 중심 구성을 선택한다. 사용자가 장소의 위치와 상세 내용을 탐색하면서 일정에 추가할 수 있어 요청한 두 흐름을 한 화면에서 연결하기 쉽다.

브라우저에서 실행하는 정적 웹사이트로 구현한다. Vite, 모듈형 JavaScript, CSS, Leaflet을 사용한다. 별도 서버, 계정, API 키, 데이터베이스는 요구하지 않는다. 지도 배경은 OpenStreetMap 타일을 사용하고 저작자 표시를 유지한다. 배경 지도는 인터넷 연결이 필요하다.

## 화면과 스타일

데스크톱에서는 상단 제목과 탐색 메뉴 아래에 장소 목록과 큰 지도를 나란히 배치한다. 장소를 선택하면 사진, 한국어 이름, 중국어 이름, 분류, 이미지에 있는 평점과 가격, 설명, 일정 추가 버튼이 있는 상세 패널을 연다. 여행 계획 보기에서는 날짜별 목록과 해당 날짜의 지도 표시를 연결한다.

밝은 아이보리 배경, 짙은 녹색, 차분한 주황색 포인트를 사용해 여행 노트 같은 인상을 만든다. 장소와 지도가 화면의 중심이 되도록 정보 밀도를 조절한다. 원본 스크린샷의 장소별 사진 영역을 CSS로 잘라 보여주고 원본 이미지 파일은 보존한다. 원본 스크린샷 전체를 확인하는 보기 기능도 제공한다.

모바일에서는 지도와 목록, 여행 계획을 탭으로 전환한다. 상세 정보는 닫을 수 있는 패널로 표시한다. 마우스 호버 없이도 모든 기능을 사용할 수 있다.

## 지도와 장소 탐색

- 27개 장소를 검색과 분류 필터로 탐색한다. 이름의 한국어·중국어 표기를 모두 검색할 수 있다.
- 분류는 전체, 자연, 명소, 사찰, 먹거리, 쇼핑, 숙소, 교통이다. 검색과 분류는 함께 적용된다.
- 마커에 마우스를 올리거나 키보드로 초점을 주면 장소 이름과 간단한 정보를 표시한다. 마커나 목록을 클릭하면 상세 패널을 열고 지도와 선택 상태를 동기화한다.
- 확대·축소와 전체 장소 보기 기능을 제공한다. 가까운 마커를 확대해서 각각 선택할 수 있어야 한다.
- 장소 좌표는 구현 중 지도 또는 신뢰할 수 있는 장소 자료로 검증한다. 정확한 지점이 확인되지 않으면 인근 지역 기준의 대략 위치로 구분하고 상세 정보에 명시한다. 근거 없는 정밀 좌표를 확정 위치로 표시하지 않는다.
- 장소 데이터에 위치 출처와 정밀도를 보관한다. 외부 지도에서 중국어 이름을 검색할 수 있는 링크를 제공한다.
- 지도 배경 로딩에 실패해도 장소 목록, 상세 패널, 일정 편집은 동작한다. 검색 결과가 없으면 빈 상태와 필터 초기화 버튼을 보여준다.

## 여행 계획

첫 실행에서는 권역별로 구성한 3일 예시 계획을 제공하고, 사용자가 확정한 일정으로 오해하지 않도록 `예시 일정`이라고 표시한다. 기본 일정은 다음과 같다.

1. 시후와 도심: 아투어 호텔 → 후빈 in77 → 시후 → 구 융진문 → 칭허팡 → 우린 야시장.
2. 사찰과 자연: 링인사 → 융푸사 → 타오광사 → 팍시사. 현지 운영시간과 체력에 맞춰 조정하도록 설명한다.
3. 운하 산책: 우린먼 선착장 → 샤오허 역사문화거리 → 궁천교 → 우린광장.

예시 일정은 모든 장소를 방문하도록 강제하지 않는다. 나머지 장소도 원하는 날에 추가할 수 있다. 확정되지 않은 출도착 항공편이나 숙박 예약은 만들어 넣지 않는다.

일정의 날짜 지정은 선택 사항이다. 날짜를 지정하지 않으면 Day 1 등의 순서로 표시한다. 사용자는 날짜별 장소를 추가·삭제하고 위·아래 버튼으로 순서를 바꾸며, 일차를 추가·삭제하고 간단한 메모를 남길 수 있다. 마지막 일차는 삭제할 수 없다. 일정이 있는 일차를 삭제하거나 전체 예시로 초기화하는 동작은 확인 단계를 둔다. 같은 장소를 같은 날에 중복 추가하지 않고 기존 항목으로 안내한다.

선택한 일차의 방문 순서를 지도에서 번호와 점선으로 표시한다. 점선은 방문 순서를 설명하는 직선 연결이며 실제 도로 경로 또는 대중교통 안내로 표현하지 않는다. 검증하지 않은 이동시간과 예약시간은 표시하지 않는다.

## 구조와 데이터 흐름

예상 구성은 `index.html`, `src/main.js`, `src/styles.css`, `src/data/places.js`, `src/map.js`, `src/itinerary.js`, `src/storage.js`, `package.json`이다. 구현 과정에서 책임에 맞게 작은 UI 모듈로 나눌 수 있다.

장소 데이터는 고정 ID, 한국어 이름, 중국어 원문, 분류, 이미지상 평점·가격, 설명, 좌표, 위치 출처·정밀도, 원본 이미지와 사진 영역으로 구성한다. 원본 파일은 프로젝트에 그대로 둔다.

화면 상태는 선택 장소, 검색어, 분류, 현재 탭, 선택 일차를 관리한다. 지도와 목록은 같은 검색 결과와 선택 상태를 사용한다. 일정에는 장소 객체를 복제하지 않고 장소 ID를 저장한다.

여행 계획은 버전이 있는 형식으로 localStorage에 자동 저장한다. 저장소 접근 실패와 잘못된 JSON은 처리하고 화면을 중단시키지 않는다. 복원할 때 일차·날짜·메모·장소 ID를 검증한다. 복원이 불가능하면 예시 일정으로 열고 안내한다. 저장에 실패한 경우 현재 세션의 편집은 유지하고 저장 실패를 알린다.

## 접근성과 오류 처리

버튼과 입력창에 명확한 이름을 제공한다. 키보드로 검색·필터·상세 열기·일정 편집을 수행할 수 있고, 초점 상태를 보이게 한다. 상세 패널을 닫을 때 기존 실행 요소로 초점을 돌린다. 이미지에는 장소 이름에 맞는 대체 설명을 제공한다. 모션 감소 설정을 존중한다.

일정에 추가한 결과와 저장 오류는 화면과 보조기기에서 인식할 수 있게 알린다. 원본 이미지 또는 지도 타일 로딩 실패를 숨기지 않는다. 사용자 메모는 HTML로 해석하지 않고 텍스트로 출력한다.

## 완료 기준과 검증

1. 원본의 27개 장소가 누락·중복 없이 반영되고 지점 구분, 평점과 원본 사진이 맞는다.
2. 지도와 목록이 연결되며 호버, 클릭, 키보드, 모바일 터치로 상세 내용을 확인할 수 있다.
3. 검색과 필터, 빈 결과와 초기화가 동작한다.
4. 일차와 날짜·메모 편집, 장소 추가·삭제·순서 변경이 동작하고 방문 순서가 지도에 반영된다.
5. 새로고침 후 계획이 유지되고, 잘못된 저장 데이터와 저장소 접근 실패에서도 화면이 열린다.
6. 위치 출처와 대략 위치를 구분한다. 이미지상 평점, 예시 일정, 직선 동선을 현재 정보나 확정 계획으로 오해하지 않게 표시한다.
7. 데스크톱과 모바일에서 화면 넘침과 가려진 조작 요소가 없는지 실제 브라우저로 확인한다.
8. 프로덕션 빌드와 일정·저장 데이터의 핵심 동작 검증을 통과한다. 실제 브라우저 검증이 불가능하면 해당 범위를 명시한다.

## 이번 범위에 포함하지 않는 항목

예약과 결제, 로그인과 서버 동기화, 실시간 교통·도보 길찾기, 확인되지 않은 영업시간·요금 수집, 배포와 도메인 연결은 포함하지 않는다. 사이트 실행 방법과 빌드 방법은 README에 제공한다.
